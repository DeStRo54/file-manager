# Покрытие регрессионных проверок

Файловый менеджер использует CLI, pathlib, os, shutil и zipfile. HTTP предоставляет только `/health`. В приложении отсутствуют shell/subprocess, tarfile и HTTP-загрузка файлов. `resolve_path` разрешает абсолютные пути и переходы к корню диска согласно справке CLI. Права файлов определяются пользователем ОС. Разделение записей БД по пользователям не является файловой песочницей.

| Категория                         | Проверяемая функция        | Сохранённое покрытие                                                                                              |
| --------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Directory Traversal               | safe_path                  | Все уникальные строки четырёх Intruder-списков; отказ или путь внутри заданного root                              |
| Zip Slip                          | validate_zip, extract_zip  | Тот же корпус для имён записей; реальные маленькие архивы, CRC, типы, коллизии, размеры и атомарность публикации  |
| XXE Injection                     | parse_xml                  | Все уникальные строки двух списков; DTD/ENTITY отклоняются до создания XML-парсера                                |
| Encoding Transformations          | пути, имена, split_command | Литеральность кодировок, Unicode, управляющие символы                                                             |
| Upload Insecure Files             | создание и чтение файлов   | Зарезервированные имена, ADS, NUL, расширения, точки и пробелы; нет запуска содержимого                           |
| Command Injection                 | имена и CLI                | Метасимволы сохраняются как данные; выполнения команд нет                                                         |
| Ограничения ресурсов              | файлы, JSON/XML, ZIP       | Граничные значения с небольшими данными вместо исчерпания ресурсов                                                |
| Файловые операции                 | FileManager                | Создание, запись, чтение, добавление, копирование, перенос, удаление, папки, JSON/XML и ZIP с тестовой заменой БД |
| Проверенные конкурентные сценарии | read_bytes/write_bytes     | Подмена inode отвергается, при одновременном создании выигрывает один поток                                       |

Все реальные операции выполняются внутри временной лаборатории. Исходные системные пути корпуса используются только как строки для проверки валидации. Сетевые подключения запрещены fixture. Документы с DTD не передаются реальному парсеру. Происхождение каждого импортированного входа, хеш исходного файла и upstream-коммит записаны в `tests/security/corpus.json`. Лицензия источника приложена.

Корпус содержит 23 198 непустых строк, объединённых в 22 709 уникальных входов. Один вход проверяется в нескольких контекстах. Точное количество запусков и результатов находится в `reports/security-regression.json` и `.md` после запуска `python ci/security_regression.py`.
