# Консольный файловый менеджер

Учебный проект на Python и PostgreSQL. Позволяет работать с файлами и папками,
читать и записывать JSON/XML, создавать и распаковывать ZIP-архивы.
PostgreSQL хранит пользователей, метаданные файлов и журнал операций;
сами файлы находятся на диске.

## Быстрый запуск приложения

Нужны **Python 3.12+** и **Docker Desktop с Linux-контейнерами**.
Команды ниже выполняются в PowerShell из папки проекта.

### 1. Установите зависимости

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Настройте подключение

Создайте `.env` из шаблона, если файла ещё нет:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Откройте `.env` и заполните `PGADMINPASSWORD` и `PGPASSWORD` двумя разными
паролями. Остальные значения для новой установки можно оставить.
Два случайных пароля можно получить командой:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32)); print(secrets.token_urlsafe(32))"
```

Для существующей БД используйте действующий пароль администратора:
изменение `.env` само по себе не меняет пароль в БД.

### 3. Подготовьте БД и запустите приложение

```powershell
docker compose up -d --wait db
.\.venv\Scripts\python.exe -m db.init_db
.\.venv\Scripts\python.exe main.py
```

`db.init_db` создаёт таблицы, процедуры и ограниченную роль приложения.
При следующих запусках достаточно первой и последней команд.
На Linux/macOS используйте `python3` для создания окружения и
`.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

## Как пользоваться

В приложении выполните `register`, задайте логин и пароль, затем войдите через
`login`. Это отдельная учётная запись приложения, а не реквизиты БД из `.env`.
Логин: 3–32 латинских буквы, цифры, `_` или `-`; пароль: минимум 8 символов.

Начните с команды `create note.txt`. Введите текст на следующих строках:
**Enter** добавляет строку, **Ctrl+S** сохраняет, **Ctrl+C** отменяет ввод.
Затем выполните `cat note.txt`, чтобы прочитать файл.

| Команды                                            | Назначение                                |
| -------------------------------------------------- | ----------------------------------------- |
| `pwd`, `ls`, `cd <путь>`                           | Навигация                                 |
| `mkdir <путь>`, `rmdir <путь>`                     | Создание и удаление пустой папки          |
| `create`, `cat`, `write`, `append`, `rm`           | Создание, чтение, запись и удаление файла |
| `cp <откуда> <куда>`, `mv <откуда> <куда>`         | Копирование и перемещение файла           |
| `json-write`, `json-read`, `xml-write`, `xml-read` | Работа с JSON/XML                         |
| `zip <источник> <архив>`, `unzip <архив> <папка>`  | Работа с ZIP                              |
| `info <путь>`, `disks`, `dbfiles`, `history`       | Информация о файлах, дисках и событиях    |
| `help`, `exit`                                     | Полная справка и выход                    |

Начальная папка — каталог запуска. Можно работать с другими папками в пределах
прав ОС; пути с пробелами заключайте в кавычки. Удаление и перезапись требуют
подтверждения. Метаданные сохраняются с абсолютными путями.
Служебная папка `data` не создаётся: одновременный запуск контролирует PostgreSQL.

Для остановки БД выполните `docker compose down` — данные сохранятся.
При ошибке подключения проверьте Docker Desktop, `.env` и выполните:

```powershell
.\.venv\Scripts\python.exe main.py --check-db
```

## Где что находится

- `main.py` — запуск; `app/cli.py` — консоль.
- `app/files/` — файловые операции, форматы и проверки.
- `db/` — подключение, подготовка и схема БД.
- `tests/` — тесты; `ci/` и `.github/` — вторая лабораторная.
