# Файловый менеджер

### Шаг 1. Установить зависимости

Перейдите в распакованную папку проекта. Если она находится в другом месте,
замените путь в первой строке:

```powershell
cd D:\projects\sdlc-file-manager-python
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Активация окружения не нужна: команды используют его интерпретатор напрямую.

### Шаг 2. Настроить подключение

Создайте `.env`, если его ещё нет, и откройте файл:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
notepad .env
```

Для новой базы оставьте значения из `.env.example`, но заполните две строки:

```text
PGADMINPASSWORD=ваш_отдельный_пароль_администратора
PGPASSWORD=ваш_отдельный_пароль_приложения
```

Это обозначения: замените текст после `=` двумя разными паролями. Можно получить
два случайных значения следующей командой и вставить их в соответствующие строки:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32)); print(secrets.token_urlsafe(32))"
```

Сохраните `.env`. В новой конфигурации `PGADMINUSER=postgres`,
`PGUSER=filemanager_app`, база `filemanager`, адрес `127.0.0.1`, порт `5432`.

Если используется **уже существующая база**, сохраните её действующие
административные реквизиты. Не заменяйте готовый `.env` шаблоном: изменение файла
не меняет автоматически пароль роли в существующем Docker-томе. Порядок перехода
со старой установки приведён в [SECURITY.md](SECURITY.md).

### Шаг 3. Запустить и подготовить базу

```powershell
docker compose up -d --wait db
.\.venv\Scripts\python.exe init_db.py
.\.venv\Scripts\python.exe main.py --check-db
```

`init_db.py` создаёт таблицы и процедуры и настраивает ограниченную рабочую роль.
При успешном выполнении выводится сообщение о подготовке схемы.
`--check-db` должен вывести версию PostgreSQL, схему и процедуры
`record_operation`, `soft_delete_file`.

### Шаг 4. Открыть приложение

```powershell
.\.venv\Scripts\python.exe main.py
```

Ожидается приветствие и приглашение `guest>`. Это означает, что приложение готово.

## 3. Быстрая проверка работы

Далее команды вводятся **внутри приложения**, а не в PowerShell.

1. Введите `register`, задайте новый логин, пароль и повтор пароля.
2. Введите `login`, затем созданный логин и пароль.
3. Выполните команды ниже по порядку:

```text
mkdir check
create check/note.txt
Проверка работы приложения.
.end
cat check/note.txt
dbfiles
history 5
exit
```

`cat` должен показать введённый текст, `dbfiles` — сведения о файле,
`history` — события. `.end` вводится отдельной строкой и завершает ввод текста.
При повторной проверке используйте новую учётную запись, чтобы папка `check`
не совпала с существующей.

Пароль пользователя приложения отличается от паролей БД в `.env`. Логин содержит
3–32 латинских буквы, цифры, `_` или `-`; пароль — минимум 8 символов.
В интерактивном терминале ввод пароля скрыт: отсутствие символов на экране нормально.

Полный сценарий проверки JSON/XML, архивов и защиты находится в [DEMO.md](DEMO.md).
Команда `help` показывает встроенную справку.

## 4. Повторный запуск готовой установки

Если окружение и база уже подготовлены, достаточно:

```powershell
docker compose up -d --wait db
.\.venv\Scripts\python.exe main.py
```

Повторять установку зависимостей и `init_db.py` при каждом запуске не требуется.
Войдите командой `login`: учётные записи и файлы сохраняются между запусками.

Для остановки завершите приложение командой `exit`, затем в PowerShell выполните:

```powershell
docker compose down
```

Эта команда сохраняет том базы. Не добавляйте `-v`, если данные нужно сохранить.

## 5. Если приложение не запускается

| Симптом                                          | Что проверить или сделать                                                                                                               |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `py` не найден                                   | Установить Python с launcher либо использовать доступную команду `python` вместо `py -3` при создании окружения                         |
| Не найден `.venv\Scripts\python.exe`             | Выполнить шаг создания окружения из папки проекта                                                                                       |
| `ModuleNotFoundError: psycopg` или `psutil`      | Установить `requirements.txt` именно через интерпретатор `.venv`                                                                        |
| Docker недоступен, ошибка подключения к движку   | Запустить Docker Desktop, проверить Linux engine и разрешения пользователя на доступ к Docker                                           |
| Compose сообщает об отсутствии `PGADMINPASSWORD` | Заполнить соответствующую строку `.env` и сохранить файл                                                                                |
| Порт `5432` занят                                | Установить `PGPORT=5433` в `.env` и повторить `docker compose up -d --wait db`                                                          |
| Ошибка PostgreSQL                                | Проверить состояние контейнера, реквизиты `.env`, затем выполнить `--check-db`; на новой установке убедиться, что выполнен `init_db.py` |
| Ошибка административных прав при обычном запуске | Проверить `PGUSER=filemanager_app`; административная роль задаётся отдельно через `PGADMINUSER`                                         |
| Найден `manager.lock`                            | Закрыть другую копию приложения; удалять блокировку только после проверки, что программа не работает                                    |
| Логин уже занят или файл уже существует          | Войти в прежнюю учётную запись либо создать новую для чистой демонстрации                                                               |
| Вход временно заблокирован                       | После пяти неверных попыток подождать одну минуту и проверить пароль                                                                    |

Диагностика контейнера:

```powershell
docker compose ps
docker compose logs --tail 50 db
.\.venv\Scripts\python.exe main.py --check-db
```

Если после аварии программа точно завершена, оставшуюся блокировку можно удалить:

```powershell
Remove-Item -LiteralPath .\data\manager.lock
```

Для пользовательского каталога `--data` удаляется блокировка в этом каталоге,
а не обязательно в `data`. При предупреждении о незавершённых операциях войдите
и выполните `reconcile`: команда выводит отчёт без изменения данных.

Переменные окружения `PG*`, заданные в терминале, имеют приоритет над `.env`.
Если настройки не совпадают с файлом, проверьте также окружение процесса.

## 6. Автоматические тесты

При работающей базе и заполненных административных и рабочих реквизитах:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты создают отдельную схему `fm_test_*` и временные папки и удаляют их после
проверки. Данные рабочей схемы и каталога `data` не используются как тестовые.
Ожидаемый итог — `OK`. Результаты предыдущего прогона и ограничения среды проверки
описаны в [TESTING.md](TESTING.md).

## 7. Запуск на Linux или macOS

Из папки проекта выполните:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
if [ ! -f .env ]; then cp .env.example .env; fi
```

Откройте `.env` в редакторе, задайте два разных пароля, как в шаге 2, затем:

```bash
docker compose up -d --wait db
.venv/bin/python init_db.py
.venv/bin/python main.py --check-db
.venv/bin/python main.py
```

При повторном запуске достаточно поднять контейнер и выполнить последнюю команду.
