# Результаты проверок

## После усиления защиты

Добавлены 8 автономных проверок в `tests/test_security.py`: общая квота и
перезапись, число папок, неявные папки ZIP, нехватка места, сверка без изменений,
отсутствие пароля до подключения, отказ административной роли и сохранение исходной
ошибки при отказе журнала. Все 8 прошли; также прошли 3 прежних FormatTests.
В среде Windows sandbox запуск файловых тестов требовал временного обхода создания
каталогов с mode=0700 в тестовом процессе: ACL таких каталогов блокирует sandbox.
Права каталогов в этом прогоне не проверялись; производственный код не ослаблен.
Синтаксис Python проверен через compileall.

В ManagerTests добавлены проверки запрета DDL и изменения журнала, квот и сверки.
Полный прогон после изменений: **26 тестов прошли** на Windows, Python 3.14,
PostgreSQL 17.11 (сервер в Docker, подключение напрямую через 127.0.0.1:5432).
Docker API недоступен из sandbox, но TCP-подключение к PostgreSQL работает.
Для тестового CLI-подпроцесса также использован обход mode=0700 через временный
sitecustomize в игнорируемом .test-harness; ограничения прав ОС этим прогоном не проверены.
На рабочей public-схеме отдельно подтверждены отсутствие SUPERUSER/CREATEDB/CREATEROLE,
запрет CREATE в схеме и прямых INSERT/UPDATE/DELETE журнала, доступ к чтению журнала
и процедуре записи. После прогона схем fm*test*\* не осталось.
Внесена проверка исходного имени ZIP до нормализации Windows и исправлена вредоносная
ZIP-фикстура, чтобы при создании она не теряла обратный слеш.
Прежний результат ниже относится к версии до усиления защиты.

Для полного прогона задайте PGADMIN* и PG* в .env, запустите PostgreSQL и выполните:

```bash
python init_db.py
python -m unittest discover -s tests -v
```

## Прежняя версия

Дата: 9 октября 2026 года. Среда: Linux, Python 3.12.14, PostgreSQL 17.10,
psycopg 3.3.6, psutil 7.2.2.

**15 тестов прошли, ошибок и пропусков нет.** Запуск:

```bash
docker compose up -d
python -m unittest discover -s tests -v
```

Тесты используют временные папки и одну новую схему `fm_test_*` на весь запуск.
Рабочие файлы и схема приложения не меняются. Схема удаляется в конце проверки.

| Конкурентный вход | Два отдельных соединения сохраняют обе неверные попытки через FOR UPDATE                         |
| Файлы и папки     | Создание, чтение, дозапись, замена, копирование, перемещение, удаление, навигация                |

## Границы учебной реализации

- БД и файлы не образуют общую транзакцию; аварийное завершение может оставить
  started без результата и расхождение метаданных с файлами.
- Контроль доступа действует для учётных записей приложения. Пользователь ОС
  с правами на папку или реквизитами БД может менять данные вне приложения.
- Блокировка защищает от второй копии программы. Полной защиты от другого
  процесса того же пользователя ОС, подменяющего папки между проверками, нет.
- Внешние изменения файлов автоматически не отслеживаются; ls читает папку,
  dbfiles показывает учтённые приложением записи.
- Копирование/перемещение поддерживаются для файлов; rmdir удаляет пустые папки.
  Для переноса дерева папок предусмотрен ZIP.
- ZIP поддерживает обычные STORE/DEFLATE без пароля. Текст читается как UTF-8.
